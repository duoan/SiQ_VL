% ─── Abstract ───────────────────────────────────────────────────────────────
\begin{abstract}
We present a systematic study of single-GPU training efficiency optimization
for SiQ-VL, a small-scale (0.5B parameter) vision-language model trained on
an NVIDIA RTX PRO 6000 Blackwell GPU (96\,GB VRAM). Through 15 iterations of
measured optimizations spanning kernel fusion, data strategies, and batch scaling,
we improve effective throughput from 21.7K to 107.4K real tokens/second ---
a \textbf{4.95$\times$ speedup}. We identify the throughput ceiling imposed by
Model FLOPs Utilization (MFU $\approx$ 22.7\%) for this model scale, demonstrate
that length bucketing eliminates 95\% of padding waste, and show that cuTile
(TileGym) kernels provide a further 14--23\% speedup at fixed tensor shapes.
All measurements use real training data with precise attention-mask accounting,
correcting earlier estimates based on synthetic benchmarks.
\end{abstract}

\vspace{1em}
\noindent\textbf{Keywords:} Vision-Language Models, Training Efficiency, GPU Kernel Optimization, cuTile, Blackwell, Sequence Packing

\section{Introduction}
\label{sec:intro}

Training vision-language models (VLMs) efficiently on a single GPU is crucial
for researchers with limited hardware budgets. While much attention has been paid
to distributed training at scale, the \emph{single-GPU efficiency frontier}
determines the baseline throughput that distributed methods multiply.

This report documents the complete optimization journey of \textbf{SiQ-VL}, a
compact VLM combining a SigLIP-2 vision encoder with a Qwen2.5 language model.
We focus exclusively on engineering optimizations that preserve model quality
(identical loss curves) while maximizing tokens processed per second.

\subsection{Contributions}

\begin{enumerate}[leftmargin=*]
  \item A \textbf{reproducible benchmark} (\texttt{benchmark\_real\_efficiency.py})
    that measures Real tok/s, Pos/s, Pad\%, and Loss\% on actual training data.
  \item Quantitative evidence that \textbf{length bucketing} at large batch sizes
    (B$\geq$64) reduces padding waste to $<$5\%, making sequence packing only
    marginally beneficial (+4.6\%).
  \item Demonstration that NVIDIA's \textbf{cuTile DSL} (via TileGym) achieves
    23\% kernel speedup but \emph{requires} quantized tensor shapes to avoid
    catastrophic JIT overhead.
  \item A complete \textbf{MFU analysis} confirming that 0.5B-scale models are
    memory-bandwidth bound at 19--23\% MFU, with throughput saturating at B$\geq$64.
\end{enumerate}

\section{Methodology}
\label{sec:method}

\subsection{Metrics}

We define four metrics measured \emph{exactly} from tensor values:

\begin{align}
  \text{Real tok/s} &= \frac{\sum_i \texttt{attention\_mask}_i.\text{sum}()}{\Delta t} \label{eq:real_toks} \\
  \text{Pos/s (hw)} &= \frac{\sum_i B_i \times N_i}{\Delta t} \label{eq:pos} \\
  \text{Pad\%} &= 1 - \frac{\text{Real tok/s}}{\text{Pos/s}} \label{eq:pad} \\
  \text{MFU} &= \frac{\text{Real tok/s} \times F_{\text{tok}}}{\text{Peak TFLOP/s}} \label{eq:mfu}
\end{align}

\noindent where $F_{\text{tok}} = 4 \times P = 4 \times 494\text{M} = 1.976$ GFLOP for Stage~1.

\subsection{Measurement Protocol}

Each configuration is measured as follows:
\begin{enumerate}
  \item Load real dataset (not synthetic) with actual images.
  \item Run $W$ warmup steps (2--10 depending on JIT overhead).
  \item Run $S=10$ measured steps, recording per-step: wall time (\texttt{cuda.synchronize}
    bracketed), \texttt{attention\_mask.sum()}, \texttt{(labels != -100).sum()}, $B \times N$.
  \item Report aggregated metrics over all $S$ steps.
\end{enumerate}

\section{Optimization Techniques}
\label{sec:techniques}

\subsection{Length Bucketing}

The standard VLM training pipeline pads all sequences in a batch to the longest.
With random sampling, padding waste scales with batch size (18--20\% at B=32).
\textbf{Length bucketing} (HuggingFace \texttt{group\_by\_length}) sorts samples
by estimated token length, ensuring each batch contains similar-length sequences.

\subsection{Sequence Packing}

Packing concatenates multiple short sequences into fixed-length bins (N=1024),
using position ID resets to maintain document boundaries. This eliminates padding
at the cost of more complex attention masking.

\subsection{TileGym (cuTile DSL Kernels)}

NVIDIA's cuTile DSL generates Blackwell-optimized kernels for matmul, attention,
and fused operations. We use TileGym to patch Qwen2's attention and MLP layers:

\begin{lstlisting}
from tilegym.transformers import apply_tilegym_kernel_to_qwen2
apply_tilegym_kernel_to_qwen2(use_cutile=True)
\end{lstlisting}

\noindent\textbf{Critical finding}: cuTile kernels use JIT compilation with per-shape
autotuning. Variable-length batches trigger recompilation on \emph{every unique shape},
causing 4--5$\times$ slowdown. The solution is \texttt{pad\_to\_multiple\_of=64} to
quantize shapes, or packing with fixed bin size.

\subsection{Fused Linear Cross-Entropy}

We implement a custom \texttt{torch.autograd.Function} that fuses the LM head
projection with cross-entropy loss using the ``grad-in-forward'' pattern:

\begin{enumerate}
  \item Chunk hidden states into blocks of 1024 tokens.
  \item For each chunk: compute logits $= Wh$, apply cross-entropy, accumulate
    $\nabla_h$ immediately, discard logits.
  \item Peak memory: $O(\text{chunk\_size} \times V)$ instead of $O(N \times V)$.
\end{enumerate}

This reduces VRAM by 51--64\% for the LM head in Stage~2.

\section{Analysis \& Discussion}
\label{sec:analysis}

\subsection{Why Throughput Saturates at B=64}

Beyond B=64 (with bucketing), Real tok/s plateaus at $\sim$90K despite VRAM
scaling linearly. This occurs because:

\begin{enumerate}
  \item \textbf{Compute saturation}: All tensor-core GEMMs are already running
    at near-peak occupancy. Adding more tokens per step increases latency
    proportionally without improving per-token efficiency.
  \item \textbf{Memory bandwidth bound}: The 0.5B model's weight matrices
    (494M $\times$ 2\,B = 988\,MB) must be read from GDDR7 regardless of batch
    size. At 1.79\,TB/s, this takes $\sim$0.55\,ms per layer --- a fixed cost
    that dominates at small GEMM shapes.
  \item \textbf{Amdahl's Law}: Non-matmul operations (softmax, RoPE, normalization)
    consume 15--20\% of step time but cannot be parallelized across batch.
\end{enumerate}

\subsection{TileGym: Power and Pitfall}

TileGym's cuTile kernels deliver 23\% speedup at fixed shapes by:
\begin{itemize}
  \item Eliminating kernel launch overhead via persistent kernels
  \item Using Blackwell-native TMA (Tensor Memory Accelerator) for loads
  \item Fusing multi-head attention with GQA natively
\end{itemize}

However, the JIT autotuner runs 20 samples per configuration to select
optimal tile sizes. With variable sequence lengths:
$$
\text{overhead} = N_{\text{unique\_shapes}} \times 20 \times t_{\text{kernel}} \approx 500\text{ms}
$$
This makes TileGym \emph{counterproductive} without shape quantization.

\subsection{Bucketing vs.\ Packing: A Nuanced Picture}

\begin{table}[h]
\centering

\noindent The 4.6\% gain from packing is real but modest. Packing becomes more
valuable when:
\begin{itemize}
  \item Combined with cuTile (fixed N enables kernel caching): +14\% over vanilla packing
  \item Dataset has high length variance ($\sigma / \mu > 0.5$)
  \item Multi-turn dialogues create naturally long sequences
\end{itemize}

\subsection{Loss Ratio is Dataset-Intrinsic}

The measured loss ratio (fraction of non-padding tokens that produce gradients)
is $54.3 \pm 1.5\%$ across all configurations. This is determined entirely by
the chat template structure (system prompt + question = no gradient, answer = gradient)
and is \emph{independent} of engineering choices.

\section{Conclusion \& Future Work}
\label{sec:conclusion}

We have systematically optimized SiQ-VL's single-GPU training from 21.7K to
107.4K real tokens/second (4.95$\times$), reaching the hardware efficiency
ceiling at 22.7\% MFU. The key insight is that for small (0.5B) models,
\textbf{batch scaling + shape quantization + kernel fusion} are the three
levers that matter; advanced techniques like sequence packing provide only
marginal additional gains over effective length bucketing.

\subsection{Future Directions}

\begin{enumerate}[leftmargin=*]
  \item \textbf{Scale up}: Moving to Qwen2.5-3B/7B will increase MFU to
    35--50\% by enabling larger GEMM shapes.
  \item \textbf{Scale out}: Multi-GPU training on Modal (FSDP2 + tensor
    parallelism) multiplies single-GPU throughput by $N_{\text{GPUs}}$.
  \item \textbf{FP8 training}: Blackwell's FP8 tensor cores offer 2$\times$
    peak TFLOP/s; FP8 training could double throughput when stable.
  \item \textbf{Longer sequences}: Multi-turn data with 4K--8K tokens would
    better amortize per-batch fixed costs and improve MFU.
  \item \textbf{Overlapped execution}: Pipelining vision encoder + LLM
    forward across CUDA streams to hide sequential dependency.
\end{enumerate}
